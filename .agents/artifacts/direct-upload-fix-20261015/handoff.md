## Implemented code

- Direct session create JSON accepts optional `replaceId` only for native/browser HTML, not guest. Session identity is distinct from target identity. The server echoes `replaceId` before any part upload so clients fail safely against old servers.
- Additive upload_sessions columns are target_id, expected_object_key, and receipt. The unique artifact_id still owns a staging body. Replacement keys are `transfers/<target>/<stagingId>`.
- New `publisher/src/html-versions.ts` owns a conditional UPDATE-only pointer commit. It locks the current row, checks legacy operation ownership and the expected key, merges omitted project with current project, and returns full before/after snapshots. Stored raw body hash and size are verified first. Duplicate completion returns the saved result. Replacement receipts and UUID bindings are retained past normal pruning.
- Legacy multipart HTML replacement now stages a separate immutable key, reads and hashes the stored body, uses the same conditional commit, and stores a full receipt in upload_sessions. Journal hydration keeps old JSON strings. Stale or revoked old journal records cannot upsert over newer metadata or clear revocation.
- Explicit revoke marks the existing row revoked and retains a tombstone. Deletion reads current and retained receipt keys, aborts/list-deletes only the artifact's exact version prefix plus fixed historical keys. Session cleanup removes only its unpublished key and retries revoked/failed replacement cleanup. No bulk migration, rewrite, rename, or re-upload exists.
- File delivery defaults PDFs to inline. It recognizes application/pdf and binary-classified names ending .pdf so retained PDFs need no metadata change. Signed storage requests override MIME and disposition. `?download=1` forces attachment. HTML sandbox/favicon handling is preserved. A shared URL builder returns downloadUrl for files and the Library adds Download.
- Browser Replace uses the existing direct client and keeps the same button. It checks the replacement target acknowledgement and returned ID, and never creates a new UUID automatically for an expired replacement.
- Fleet canonical upload.py now sends all creates and replacements through the existing direct uploader. All existing flags remain. Request UUID recovery works for HTML too. It checks source identity, size, SHA-256, target ID, canonical URL, and the initialization target acknowledgement. No multipart fallback remains in that client.
- Fleet adds `--skill file-upload` to update-fleet and verify-fleet. It uses existing bundle/SSH/target machinery, changes only canonical file-upload plus all declared harness links, and skips all secrets and unrelated managed state. No installed target was updated.
